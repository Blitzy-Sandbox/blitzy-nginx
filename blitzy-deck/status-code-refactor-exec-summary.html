Blitzy Engineering Brief

NGINX HTTP Status-Code
Registry Refactor

From scattered constant-based assignments to a centralized, registry-backed API with optional RFC 9110 validation — full backward compatibility, byte-identical wire output.

Blitzy NGINX 1.29.5  |  Executive Summary

Executive Summary

One authoritative model for every HTTP status code

Goal

Consolidate three unlinked status definitions and 33 scattered field writes behind a single registry and a five-function API.

Approach

Introduce ngx_http_status_def_t and ngx_http_status_*(); route reason-phrase and error-page lookups through it.

Guarantee

Byte-identical status lines and error pages; preserved ABI, filter signatures, and upstream pass-through.

Refactor — not a runtime bug fix. The "defect" is a set of architectural deficiencies addressed at their source.

Root Cause Analysis

Five interlocking deficiencies

RC-1 Triple definition

The same code set declared in three compiler-unlinked artifacts.

RC-2 No chokepoint

Direct r->headers_out.status = writes; nowhere to validate or instrument.

RC-3 Divergent macros

NGX_HTTP_LAST_2XX = 207 vs 202 — a concrete latent defect.

RC-4 No validation seam

No API to validate against RFC 9110 or register new codes.

RC-5 Sparse metadata

Many codes carry ngx_null_string reasons and no class / cacheability fields.

The Model

Registry descriptor and flag bits

typedef struct {
    ngx_uint_t   code;        /* e.g. 404 */
    ngx_str_t    reason;      /* "Not Found" (or empty -> numeric-only) */
    ngx_uint_t   flags;       /* class + cacheability bitmask */
    const char  *rfc_section; /* "15.5.5" */
} ngx_http_status_def_t;

#define NGX_HTTP_STATUS_CACHEABLE      0x0001
#define NGX_HTTP_STATUS_CLIENT_ERROR   0x0002
#define NGX_HTTP_STATUS_SERVER_ERROR   0x0004
#define NGX_HTTP_STATUS_INFORMATIONAL  0x0008

Cacheable-by-default metadata set: 200, 203, 204, 206, 300, 301, 308, 404, 405, 410, 414, 501 (exposes RFC 9111 heuristic cacheability; no new caching behavior).

The API Surface

Five functions, each ≤ 50 lines

FunctionRole
ngx_http_status_set()The assignment chokepoint (replaces direct field writes).
ngx_http_status_validate()RFC 9110 conformance check (100–599).
ngx_http_status_reason()Reason-phrase accessor (replaces table arithmetic).
ngx_http_status_register()Worker-init extensibility seam.
ngx_http_status_is_cacheable()Cacheability flag test.

Declared via ngx_http.h; implemented in ngx_http_status.c. An idempotent ngx_http_status_init() hook populates the registry before worker fork.

Migration Pattern

Same wire output, one mechanical change

/* OLD */
r->headers_out.status = NGX_HTTP_NOT_FOUND;
/* NEW */
if (ngx_http_status_set(r, 404) != NGX_OK) {
    ngx_log_error(NGX_LOG_ERR, r->connection->log, 0,
                  "invalid HTTP status %ui",
                  (ngx_uint_t) 404);
    return NGX_HTTP_INTERNAL_SERVER_ERROR;
}

Backward Compatibility

Non-negotiable invariants preserved

Byte-identical wire

Status lines and error-page bodies diff to empty before/after, including numeric-only placeholder codes.

Security rewrites

494/495/496/497 → 400 wire-rewrite and 498 → error_404_page mapping unchanged.

Upstream pass-through

Proxied status is copied, never strict-validated.

Stable ABI

NGX_MODULE_V1 and all filter-chain signatures untouched; bodies only.
